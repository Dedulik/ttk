# Карта пространства · Ростов Арена

Веб-приложение для навигации по стадиону «Ростов Арена» и его территории. Кейс ТТК «Карта пространства».

- **Посетитель** открывает карту по ссылке с телефона. Он видит 3D-модель стадиона и территории, ищет сектор или кафе, строит маршрут и проходит его по панорамам 360°. С любого сектора можно посмотреть «вид с места».
- **Сотрудник** входит в админ-панель и рисует помещения: прямоугольники, контуры, овалы, стены, двери, лестницы. Затем ставит ключевые метки и точки панорам, связывает их переходами, раскрашивает карту и публикует. Права зависят от роли.

| Экран | Адрес |
| --- | --- |
| Карта для посетителей | `/` |
| Карта другого объекта | `/?object=<адрес объекта>` |
| Личная ссылка администратора (все его опубликованные объекты) | `/?by=<адрес автора>` |
| Ссылка на место | `/#/place/A105`, `/#/place/m1` |
| Админ-панель (отдельная страница) | `/admin` или `/admin.html` |
| Конструктор объекта | `/admin.html#/edit/<адрес объекта>` |

## Админ-панель

Отдельная страница `frontend/admin.html`. На карту для посетителей ведёт кнопка «Админ-панель» вверху и ссылка «Для сотрудников» в шторке.

- **Объекты.** Список всех карт. Администратор создаёт объект с пустого плана (участок нужного размера), копией существующего объекта или из шаблона «Ростов Арены». Потом рисует его в конструкторе: подложка (свой план или чертёж), помещения, стены, двери, лестницы, метки, панорамы. Затем публикует. Карта объекта открывается по ссылке `/?object=<адрес>`.
- **Личный кабинет.** Имя, смена пароля (нужен текущий, остальные устройства выходят), «выйти на всех устройствах», свои последние действия.
- **Команда.** Все администраторы и сотрудники с фильтром по роли: роли, блокировка и разблокировка, отключение доступа, сброс пароля, удаление.
- **Безопасность.** Проверка настроек, резервная копия базы одной кнопкой, журнал всех действий с IP-адресами.

### Защита базы данных

- Пароли хранятся как хэш PBKDF2-SHA256 (200 000 итераций, соль). Новый пароль должен быть от 8 символов, с буквами и цифрами.
- После 5 неверных паролей учётная запись блокируется на 15 минут. С одного IP-адреса допускается не больше 20 ошибок за 10 минут.
- Смена пароля, отключение сотрудника и «выйти везде» отзывают все токены сразу.
- Если `SECRET_KEY` не задан, сервер сам создаёт случайный ключ в `backend/data/secret.key`.
- При каждом запуске сервер делает копию базы в `backend/data/backups/` и хранит последние 10 (`BACKUP_KEEP`).
- Заголовки CSP, `nosniff` и `X-Frame-Options`. Ответы API не кэшируются. В SQLite включён `secure_delete`.

## Быстрый старт

Нужен Python 3.10+. Node.js не нужен: фронтенд работает без сборки.

```bash
cd backend
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python run.py                    # → http://localhost:8000
```

При первом запуске создаются база `backend/data/app.db`, шаблон карты по генплану и три учётные записи:

| Роль | Почта | Пароль |
| --- | --- | --- |
| Администратор | admin@arena.local | admin12345 |
| Редактор | editor@arena.local | editor12345 |
| Наблюдатель | viewer@arena.local | viewer12345 |

> Перед показом на сервере смените `SECRET_KEY` и пароль администратора. Учебные учётные записи отключаются так: `SEED_DEMO_USERS=0` (см. `backend/.env.example`).

### Через Docker

```bash
docker compose up --build        # → http://localhost:8000, данные в томе arena-data
```

### Демо без сервера

`frontend/` можно открыть как статический сайт: GitHub Pages, `python -m http.server` в папке `frontend`. Без бэкенда приложение переходит в демо-режим. Роли и публикация работают так же, но данные хранятся в браузере. Публикация на GitHub Pages настроена в `.github/workflows/pages.yml`.

## Роли и права

| Действие | Посетитель | Наблюдатель | Редактор | Администратор |
| --- | :-: | :-: | :-: | :-: |
| Смотреть опубликованную карту, панорамы, маршруты | ✓ | ✓ | ✓ | ✓ |
| Смотреть черновик и историю версий | | ✓ | ✓ | ✓ |
| Рисовать помещения, ставить метки и панорамы, сохранять черновик | | | ✓ | ✓ |
| Загружать фото и панорамы 360° | | | ✓ | ✓ |
| Публиковать, откатывать версии | | | | ✓ |
| Управлять пользователями и ролями | | | | ✓ |

Права проверяет сервер (`backend/app/security.py`, декоратор `require_role`). Интерфейс только прячет недоступные кнопки. Роль берётся из базы при каждом запросе, поэтому понижение прав действует сразу.

```

  app/security.py        пароли (PBKDF2), JWT, роли
  app/api/auth.py        вход
  app/api/maps.py        карта: опубликованная версия, черновик, публикация, история
  app/api/users.py       пользователи (только администратор)
  app/api/uploads.py     фото и панорамы 360°
  tests/test_api.py      проверки ролей, конфликтов, публикации, загрузок
frontend/                чистые ES-модули, без сборки
  index.html             точка входа, three.js подключён из vendor/
```

### Черновик и публикация

Редакторы работают с одним общим **черновиком**. Он автоматически сохраняется через 2,5 с после правки, вручную — Ctrl+S. Если двое правили одновременно, сервер вернёт конфликт 409, и второй редактор загрузит свежую версию. Посетители видят только **опубликованную версию**. Каждая публикация — новая запись в истории, к любой можно вернуться.

### Телефон

- 3D управляется как в картах: один палец сдвигает карту, два — масштаб и поворот.
- В панораме палец поворачивает взгляд, щипок приближает, нажатие на землю ведёт в ту сторону.
- Подписи в 3D держат постоянный размер в пикселях, шрифт интерфейса — 14 px.
- На слабых устройствах включается облегчённый режим без теней, вручную — `?lite` в адресе.
- 3D перерисовывается только при изменениях, чтобы экономить батарею.
