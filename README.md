# Карта пространства · Манеж ДГТУ

Интерактивная веб-платформа для навигации по площадкам мероприятий: 3D- и 2D-карта, панорамы 360° с переходами между точками, маршруты и маскот-помощник. Кейс компании ТТК «Карта пространства», команда ХХХХ. Главный объект — Манеж ДГТУ, второй объект — стадион «Ростов Арена» (`/?object=rostov-arena`).

Рабочая версия: **https://193-233-246-152.sslip.io** (админ-панель — `/admin`).

Проект сочетает:

- 3D-модель площадки на three.js и 2D-план на SVG;
- панорамы 360° с переходами по стрелкам и анимацией «ладошкой»;
- конструктор карт для организатора — без программиста;
- съёмку панорамы камерой телефона (16 кадров) со склейкой прямо в браузере;
- backend на Python (Flask + SQLite) с ролями, черновиками, версиями и журналом действий;
- PWA: карту можно установить на телефон и открыть без сети.

## Возможности

- Просмотр площадки в 3D и на 2D-плане, переключение без потери выбранного места.
- Поиск залов, входов, кафе и других мест; быстрые категории «Входы», «Еда», «Туалеты», «Кассы», «Панорамы».
- Маршрут от точки до точки с расстоянием в метрах — на карте и по панорамам (стрелка «Дальше»).
- Панорамы 360° (4096×2048): стрелки к соседним точкам, мини-карта, полный экран, снимок вида, ссылка «Поделиться».
- «Спросите маскота»: вопросы вроде «где туалет?» или «как пройти на регистрацию?» — ответ местами с карты и кнопкой «Маршрут».
- Маскот ТТК рассказывает о месте в панораме (текст задаёт организатор).
- «Пиксельная охота»: посетитель ищет пиксели ТТК в панорамах, прогресс — в личном кабинете, есть таблица лидеров.
- Конструктор: помещения, контуры, овалы, стены, двери, лестницы, этажи, метки, точки панорам и переходы; черновик, проверка карты, публикация и откат версий.
- Съёмка панорамы камерой телефона с подсказками гироскопа; кадры сохраняются в браузере, их можно переснять по одному или очистить все сразу.
- Роли «посетитель», «наблюдатель», «редактор», «администратор»; приглашения сотрудников по одноразовой ссылке.
- Адаптация под телефон: шторка по стрелке, жесты как в картах, облегчённый режим на слабых устройствах.

## Архитектура

### 1. Источники данных

Карта объекта — один JSON-документ: помещения (`shapes`), стены, двери, лестницы, этажи, метки (`pois`), точки панорам (`panos`), переходы между ними (`links`), стиль и тексты маскота. Формат описан в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

Откуда берётся карта:

- `frontend/data/manezh_dgtu_map.json` — исходная карта Манежа ДГТУ. На пустой базе сервер создаёт из неё черновик и версию 1. Если карту никто не правил, сервер обновляет её из репозитория при запуске.
- `map_drafts` — общий черновик, который правят редакторы в конструкторе.
- `map_versions` — опубликованные версии; посетители видят последнюю.
- `uploads` — фото, панорамы 360° и видео переходов, загруженные сотрудниками (`/uploads/...`).
- Демо-режим: если сервера нет, фронтенд берёт карту из репозитория и хранит правки в браузере.
- IndexedDB браузера — кадры съёмки панорамы до склейки (можно прервать и продолжить).

### 2. Backend слой

Основные модули backend:

- `backend/app/__init__.py`
  - создание Flask-приложения и регистрация маршрутов;
  - начальные данные: объекты и первый администратор (пароль придумывает сервер);
  - резервная копия базы при каждом запуске;
  - заголовки безопасности: CSP, `nosniff`, `X-Frame-Options`, `Permissions-Policy`;
  - отдача сайта и загруженных файлов.
- `backend/app/security.py`
  - хэширование паролей PBKDF2-SHA256, 200 000 итераций;
  - JWT (HS256) с версией токена — смена пароля отзывает все сеансы;
  - декоратор `require_role`: роль проверяется по базе при каждом запросе;
  - блокировка после неверных паролей и ограничение частоты запросов.
- `backend/app/api/maps.py`
  - объекты: список, создание (пустой план, копия, шаблон), переименование, удаление;
  - черновик с номером ревизии: одновременная правка двумя редакторами возвращает конфликт 409;
  - «замок» конструктора: один редактор за раз, замок истекает через 2 минуты тишины;
  - проверка и очистка JSON карты, публикация, история версий, откат.
- `backend/app/api/uploads.py` — приём JPG/PNG/WebP, панорам 360° (проверка пропорции 2:1) и видео MP4/WebM с проверкой сигнатуры файла.
- `backend/app/api/auth.py`, `users.py`, `invites.py` — вход, регистрация посетителей, профиль, сотрудники, приглашения по одноразовой ссылке (в базе хранится только хэш токена).
- `backend/app/api/quest.py` — «Пиксельная охота»: найденные пиксели и таблица лидеров.
- `backend/app/api/admin.py` — журнал действий, проверка настроек безопасности, скачивание резервной копии.

### 3. Frontend слой

Основные модули frontend:

- `src/visitor/visitor.js`
  - стартовая шторка, поиск, карточки мест, маршрут;
  - режим панорамы: стрелки, мини-карта, переходы «ладошкой», полный экран, снимок, ссылка;
  - «Пиксельная охота» и продолжение с последней панорамы.
- `src/core/scene3d.js` — 3D-сцена на three.js: модель площадки, метки, точки панорам, сфера панорамы, маршрут, выделение выбранной точки неоновым свечением.
- `src/core/plan2d.js` — 2D-план на SVG: жесты (сдвиг, щипок, колесо), подписи постоянного размера, слои.
- `src/core/model.js`, `src/core/nav.js` — геометрия, поиск мест, маршрут по графу панорам и пешеходный путь A* в обход стен.
- `src/visitor/assistant.js` — «Спросите маскота»: разбор вопроса по ключевым словам, работает в браузере без отправки данных.
- `src/core/mascot.js`, `src/core/palm.js` — маскот ТТК (позы, облако с текстом, звук) и переход «ладошкой» по нарезанным кадрам.
- `src/admin/admin.js`, `src/admin/tools.js` — конструктор: инструменты рисования, инспектор свойств, настройка панорамы, публикация.
- `src/admin/capture.js`, `src/admin/stitch-worker.js` — съёмка 16 кадров камерой и склейка в фоновом потоке.
- `src/admin/cabinet.js` — вход, регистрация, личный кабинет, команда, безопасность.
- `src/core/api.js` — единый клиент API, демо-режим и экран «Сервер не отвечает».
- `sw.js` — сервис-воркер: опубликованные карты и картинки работают без сети; вход и админ-панель не кэшируются.

### 4. Поток данных

```
manezh_dgtu_map.json / конструктор / загрузки фото и видео
                │
                ▼
     Flask API  /api/*   (роли, проверка, журнал)
                │
                ▼
   SQLite: черновик ──публикация──▶ версии карты      файлы: /uploads/*
                │                         │                  │
                ▼                         ▼                  ▼
     Конструктор (сотрудники)     GET /api/venues/<объект>/map + фото панорам
                                          │
                                          ▼
                    Браузер посетителя (кэш PWA для офлайна)
                                          │
                                          ▼
            3D-сцена three.js / 2D-план SVG / панорамы 360° / маскот
```

Съёмка панорамы идёт отдельно и почти целиком в браузере:

```
камера + гироскоп ─▶ 16 кадров (IndexedDB) ─▶ Web Worker: выравнивание, яркость, склейка 4096×2048
                                                        │
                                                        ▼
                                  предпросмотр ─▶ POST /api/uploads (kind=pano360) ─▶ точка карты
```

Склейка в `stitch-worker.js`:

1. Кадры раскладываются по сфере по показаниям гироскопа.
2. Кадры выравниваются по изображению: сначала грубо по уменьшенным копиям, потом точнее, начиная от первого кадра. Если угол обзора камеры не задан вручную, он подбирается сам.
3. Яркость и цвет каждого кадра подравниваются по перекрытиям с соседями.
4. Кадры смешиваются с узким швом, непокрытые места (полюса) заполняются плавным продолжением цвета.

### Backend

- Python 3.12 (локально — от 3.10)
- Flask 3
- PyJWT 2
- SQLite (встроен в Python)

### Frontend

- JavaScript (ES-модули, без сборщика и без Node.js)
- three.js r160
- SVG для 2D-плана
- Web Workers, IndexedDB, Service Worker (PWA)

### Инфраструктура

- Docker, Docker Compose

- VPS Aeza (Ubuntu), файрвол ufw
- GitHub Actions — тесты на каждый push

## API

Все ответы — JSON. Ошибка — `{"detail": "текст"}` с кодом 4xx. Авторизация — заголовок `Authorization: Bearer <token>`. Уровни доступа: все → посетитель → наблюдатель → редактор → администратор (каждый следующий может всё, что предыдущий).

### Служебные маршруты

| Метод | Путь | Доступ | Описание |
| --- | --- | --- | --- |
| GET | `/api/health` | все | проверка, что сервер жив |
| GET | `/uploads/<файл>` | все | загруженные фото, панорамы, видео |

### Вход и профиль

| Метод | Путь | Доступ | Описание |
| --- | --- | --- | --- |
| POST | `/api/auth/register` | все | регистрация посетителя → `{token, user}` |
| POST | `/api/auth/login` | все | `{email, password}` → `{token, user}` |
| GET | `/api/auth/me` | посетитель | текущий пользователь |
| PATCH | `/api/auth/me` | посетитель | имя, адрес личной ссылки, смена пароля |
| POST | `/api/auth/logout-all` | посетитель | выйти на всех устройствах |
| GET | `/api/auth/me/activity` | посетитель | свои последние действия |

Параметры `POST /api/auth/register`:

- `email`, `name` (от 2 символов), `password` (от 8 символов, буквы и цифры);
- роль всегда «посетитель» — поля роли из запроса игнорируются.

Параметры `PATCH /api/auth/me`:

- `name`, `handle`;
- `new_password` вместе с текущим `password`.

### Объекты и карты

| Метод | Путь | Доступ | Описание |
| --- | --- | --- | --- |
| GET | `/api/venues` | все | опубликованные объекты; сотрудникам — все, с состоянием черновика |
| GET | `/api/venues/by/<handle>` | все | опубликованные объекты автора (личная ссылка) |
| POST | `/api/venues` | администратор | создать объект |
| PATCH | `/api/venues/<объект>` | администратор | название и описание |
| DELETE | `/api/venues/<объект>` | администратор | удалить объект (нужно подтвердить адрес) |
| GET | `/api/venues/<объект>/map` | все | последняя опубликованная версия |
| GET | `/api/venues/<объект>/draft` | наблюдатель | черновик с номером ревизии |
| POST | `/api/venues/<объект>/lock` | редактор | взять или продлить «замок» конструктора |
| DELETE | `/api/venues/<объект>/lock` | редактор | отпустить «замок» |
| PUT | `/api/venues/<объект>/draft` | редактор | сохранить черновик |
| POST | `/api/venues/<объект>/publish` | администратор | опубликовать черновик |
| GET | `/api/venues/<объект>/versions` | наблюдатель | история публикаций |
| POST | `/api/venues/<объект>/versions/<id>/restore` | администратор | вернуть версию в черновик |

Параметры `POST /api/venues`:

- `name` — название;
- `slug` — адрес латиницей (не задан — строится из названия);
- `start` — `blank` (пустой участок `width`×`height` метров), `copy` (копия объекта `source`) или `template` (шаблон «Ростов Арены»).

Параметры `PUT /api/venues/<объект>/draft`:

- `data` — JSON карты (до 2 МБ, проверяется и очищается сервером);
- `base_revision` — ревизия, с которой редактор начинал. Если черновик уже изменил другой — ответ 409.

Параметры `POST /api/venues/<объект>/publish`:

- `comment` — комментарий к версии, до 300 символов.

### Загрузка файлов

| Метод | Путь | Доступ | Описание |
| --- | --- | --- | --- |
| POST | `/api/uploads` | редактор | multipart, поле `file` → `{id, url, width, height}` |

Параметры `POST /api/uploads`:

- `kind` не задан — фото JPG/PNG/WebP до 15 МБ (`MAX_UPLOAD_MB`), до 16384 px по стороне;
- `kind=pano360` — то же, плюс пропорция 2:1 и ширина от 2000 px;
- `kind=video` — видео перехода MP4 (H.264) или WebM до 60 МБ (`MAX_VIDEO_MB`).

Важно:

- тип файла проверяется по содержимому (сигнатуре), а не только по расширению;
- не больше 120 файлов за 10 минут от одного пользователя.

### Пользователи и приглашения

| Метод | Путь | Доступ | Описание |
| --- | --- | --- | --- |
| GET | `/api/users` | администратор | список сотрудников и посетителей |
| POST | `/api/users` | администратор | создать учётную запись |
| PATCH | `/api/users/<id>` | администратор | роль, имя, пароль, отключение, разблокировка |
| DELETE | `/api/users/<id>` | администратор | удалить учётную запись |
| POST | `/api/invites` | администратор | приглашение `{email, role}` → одноразовая ссылка |
| GET | `/api/invites` | администратор | список приглашений |
| DELETE | `/api/invites/<id>` | администратор | отозвать приглашение |
| GET | `/api/invites/accept/<токен>` | все | проверить приглашение |
| POST | `/api/invites/accept/<токен>` | все | принять приглашение |

Важно:

- последнего администратора нельзя удалить или понизить;
- приглашение действует 72 часа (`INVITE_TTL_HOURS`), новое приглашение на ту же почту отменяет старое;
- если почта (SMTP) не настроена, ссылку видит администратор и передаёт её сам.

## Запуск

### Docker Compose

```bash
git clone https://github.com/Dedulik/ttk.git
cd ttk
docker compose up -d --build
docker compose exec app cat /data/admin-password.txt
```

После запуска:

- сайт: `http://localhost:8000`
- админ-панель: `http://localhost:8000/admin`, почта `admin@arena.local`, пароль — из команды выше.

С HTTPS (нужно для камеры и установки как приложения): заполните в `.env` переменные `DOMAIN`, `PUBLIC_URL`, `TRUST_PROXY=1`, `APP_BIND=127.0.0.1:8001` и запустите `docker compose --profile https up -d --build`. Пошагово для сервера Aeza — [docs/DEPLOY_AEZA.md](docs/DEPLOY_AEZA.md).

### Локально без Docker

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate              # Linux и macOS: source .venv/bin/activate
pip install -r requirements.txt
python run.py
```

После запуска:

- сайт: `http://localhost:8000`
- пароль администратора: `backend/data/admin-password.txt`

Node.js и сборка фронтенда не нужны: сервер отдаёт `frontend/` как есть.

### Демо без сервера

Папку `frontend/` можно открыть как статический сайт (GitHub Pages или `python -m http.server`). Без backend приложение работает в демо-режиме: роли и публикация те же, данные хранятся в браузере, вход — `admin@arena.local` / `admin12345`. Это только для показа: на настоящем сервере учебного пароля нет.

## Безопасность ключей и данных

- Пароли хранятся только как хэш PBKDF2-SHA256 (200 000 итераций, своя соль у каждого пароля).
- Секретный ключ подписи токенов не лежит в репозитории: задаётся через `SECRET_KEY` или создаётся сервером в `data/secret.key` с доступом только для владельца.
- Пароль администратора на сервере придумывается автоматически; учебного `admin12345` на сервере нет.
- 5 неверных паролей подряд — учётная запись блокируется на 15 минут; с одного IP — не больше 20 ошибок за 10 минут.
- Смена пароля, отключение сотрудника и «выйти везде» сразу отзывают все сеансы.
- Права проверяет сервер при каждом запросе; интерфейс только прячет недоступные кнопки.
- Запросы к базе параметризованы; JSON карты проверяется и очищается перед сохранением.
- Заголовки CSP, `nosniff`, `X-Frame-Options`; камера и датчики разрешены только своему сайту (`Permissions-Policy`).
- В SQLite включён `secure_delete`; копия базы делается при каждом запуске.
- Папка `backend/data/` (база, ключ, пароль, загрузки) и файлы `.env` не попадают в git.
- Сайт работает по HTTPS; старые ссылки `http://…:8000` переадресуются на защищённый адрес.

Проверены отдельные участки приложения — подробности и найденные исправления в [docs/SECURITY_AUDIT.md](docs/SECURITY_AUDIT.md). Это не гарантия полной защищённости.

## Пользовательские сценарии

### Навигация посетителя

- Открыть карту по ссылке или QR-коду — без установки приложения.
- Найти место поиском или выбрать категорию «Туалеты», «Еда», «Входы».
- Нажать «Маршрут» и увидеть путь с расстоянием на 3D-карте или 2D-плане.

### Прогулка по панорамам

- Открыть точку обзора, осмотреться пальцем или мышью.
- Нажать стрелку к соседней точке — переход «ладошкой».
- Пройти маршрут по панорамам: стрелка «Дальше» ведёт к цели.

### Вопрос маскоту

- Нажать «Спросите маскота» и написать «где туалет?».
- Получить места с карты с кнопками «На карте» и «Маршрут».

### Подготовка площадки организатором

- Создать объект с пустого плана, копией или из шаблона; загрузить подложку — план этажа.
- Нарисовать помещения, стены, двери, расставить метки и точки панорам, связать переходы.
- Проверить карту, посмотреть «как посетитель» и опубликовать.

### Съёмка панорамы телефоном

- В конструкторе у точки нажать «Снять камерой телефона».
- Снять 16 кадров по подсказкам; любой кадр можно переснять, все — очистить кнопкой «Очистить все».
- Нажать «Собрать», проверить предпросмотр и сохранить.

### Управление командой

- Пригласить сотрудника по почте с нужной ролью.
- Сменить роль, заблокировать или отключить доступ.
- Посмотреть журнал действий и скачать резервную копию базы.

## Актуальные особенности проекта

- Посетитель видит только опубликованную версию; правки в черновике не попадают к гостям до публикации.
- В конструкторе одновременно работает один редактор («замок»); если двое всё же сохранили черновик, второй получает конфликт 409 и не затирает чужие правки.
- Права и роль проверяются по базе при каждом запросе — понижение прав действует сразу.
- Если сервер недоступен, сайт показывает экран «Сервер не отвечает» с кнопкой «Повторить», а не тихо переходит в демо.
- Панорамы хранятся в 4096×2048 — компромисс между чёткостью и памятью телефона.
- 3D перерисовывается только при изменениях, чтобы экономить батарею; на слабых устройствах — облегчённый режим (`?lite`).
- «Спросите маскота» работает целиком в браузере и никуда не отправляет вопросы.
- Переход «ладошкой» нарисован кадрами на canvas, без видеоплеера — поэтому работает и на iPhone без нажатия.

## Ограничения

- Камере и датчикам движения нужен HTTPS; на `http://` съёмка панорам недоступна.
- Качество склейки зависит от объектива: со сверхширокой камерой (0,5×) 16 кадров закрывают всю сферу, с обычной у полюсов остаются места, заполненные размытием. Близкие предметы и движущиеся люди могут давать двоение.
- База — SQLite: подходит для одного сервера и умеренной нагрузки; для большой нагрузки нужен PostgreSQL.
- «Спросите маскота» понимает вопросы по ключевым словам, а не произвольный текст.
- Адрес `sslip.io` временный; для постоянной работы нужен свой домен.
- Нужен браузер с WebGL; очень старые телефоны работают только в облегчённом режиме.
