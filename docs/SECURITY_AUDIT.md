# Аудит безопасности · октябрь 2026

Проверка проводилась на локальной копии с отдельной тестовой базой (`DB_PATH` во временной папке, учебные записи). Рабочую базу `backend/data/app.db` разрушительными тестами не трогали. Перед изменением схемы (новые таблицы `invites`, `quest_finds`, расширение ролей) сервер при запуске сделал резервную копию в `backend/data/backups/`. После миграции `PRAGMA integrity_check` и `foreign_key_check` прошли без ошибок.

Проверены отдельные участки приложения, перечисленные ниже. Это не доказывает, что приложение защищено полностью.

## Как устроена защита

| Область | Как защищено | Где в коде |
| --- | --- | --- |
| Пароли | PBKDF2-SHA256 с солью, в базе хранится только хэш. Требования: от 8 символов, буквы и цифры | `security.py` |
| Сессии | JWT, подписанный ключом из `SECRET_KEY` или из случайного `data/secret.key`. В токене есть версия (`tv`): смена пароля или «выйти на всех устройствах» отзывает старые токены | `security.py` |
| Права | `require_role` при каждом запросе берёт роль из базы, а не из токена. Понижение прав действует сразу | `security.py` |
| Регистрация | Новая учётная запись всегда получает роль «посетитель». Поля `role` и `is_admin` в запросе игнорируются. Против ботов — скрытое поле-ловушка и лимит 5 регистраций в час с одного IP | `api/auth.py` |
| Приглашения | Приглашать может только администратор. Токен — 32 случайных байта, в базе хранится только SHA-256. Ссылка одноразовая, действует `INVITE_TTL_HOURS` часов, её можно отозвать. Роль берётся из приглашения, а не из запроса. Существующий пользователь подтверждает приглашение своим паролем. Роль можно только повысить | `api/invites.py` |
| Подбор пароля | После 5 неверных паролей учётная запись блокируется на 15 минут, IP-ограничитель срабатывает на неверные токены и пароли. Лимиты: приглашения — 30 в час, загрузки — 120 за 10 минут, «Пиксельная охота» — 60 за 10 минут | `security.py`, `rate()` |
| SQL-инъекции | Все запросы с данными пользователя параметризованы (`?`). В f-строки подставляются только имена таблиц из констант и строка `?,?,?` | `db.py`, `api/*` |
| XSS | Весь пользовательский текст выводится через `esc()`. Сервер чистит карту: ссылки в `img/photo/pano/src/iconUrl` допускаются только свои (`/uploads/…`, `assets/…`), цвета — только `#rrggbb`, `embed` — только Google Maps и YouTube, ключ значка — только `[a-z0-9-]`. CSP: скрипты только свои плюс importmap по хэшу, `object-src 'none'`, `frame-ancestors 'self'` | `api/maps.py`, `__init__.py` |
| Загрузки | Тип файла определяется по содержимому (сигнатуры JPEG, PNG, WebP; у видео — `ftyp` MP4 и заголовок EBML WebM), а не по имени. Видео — до `MAX_VIDEO_MB`. В карте адрес видео перехода принимается только свой (`/uploads/…`, `assets/…`). Размер до `MAX_UPLOAD_MB`, стороны от 16 до 16 384 px. Для фото 360° сервер проверяет пропорцию 2:1 и ширину от 2000 px. Файлу даётся случайное имя, отдаётся с `nosniff` | `api/uploads.py` |
| IDOR | Черновики, версии, пользователи, журнал и приглашения доступны только по ролям. Прогресс охоты пишется только себе (`g.user`). Засчитываются только пиксели из опубликованной карты. В таблице лидеров нет почты | `api/maps.py`, `api/quest.py` |
| Одновременное редактирование | Объект редактирует один человек (замок на 120 с с продлением). Сохранение передаёт `base_revision`, при расхождении сервер отвечает 409 | `api/maps.py` |
| Секреты | `backend/data/` (база, ключ, пароль администратора, загрузки, резервные копии) в `.gitignore`. В клиентском коде секретов нет. Письма в журнал не пишутся, при ошибке отправки видно только домен | `.gitignore`, `mailer.py` |
| Офлайн-кэш (PWA) | Сервис-воркер кэширует только публичное: код, опубликованные карты, фото. Видео и запросы частями (Range) в кэш не кладутся. Вход, профиль, черновики, команда, журнал, приглашения и вся админ-панель в кэш не попадают | `frontend/sw.js` |

## Найдено и исправлено

1. **Ролей было только три, отдельной роли посетителя не было.** Если открыть регистрацию, новые записи получали бы права сотрудника. Добавлена роль `user` без доступа к админ-панели, существующая база перенесена миграцией с резервной копией.
2. **Карта принимала любые строки в ссылках и цветах.** Через черновик можно было сохранить `javascript:` в фото или `"><script>` в поле встраивания. Теперь сервер такие значения выбрасывает, слишком длинные строки отклоняет (422), а id объектов проверяет по шаблону.
3. **Загрузка проверяла только тип файла.** Картинка 40 000 × 20 000 px проходила и подвешивала браузер. Теперь размеры читаются из заголовка файла и ограничиваются, а для фото 360° проверяется пропорция.
4. **Не было защиты от массовой регистрации.** Добавлены лимит по IP и поле-ловушка.
5. **Ключ значка не проверялся.** Теперь допускаются только `[a-z0-9-]`.

## Что осталось и что рекомендуем

- **Токен хранится в `localStorage`.** Если на сайте найдётся XSS, токен можно украсть. Сейчас этот риск снижают CSP и экранирование. Надёжнее перейти на cookie `HttpOnly; Secure; SameSite=Strict` с CSRF-токеном.
- **Учебные записи.** На пустой базе сервер создаёт `admin@arena.local / admin12345`, а при `SEED_DEMO_USERS=1` — ещё редактора и наблюдателя. В продакшене задайте `ADMIN_PASSWORD`, поставьте `SEED_DEMO_USERS=0` и проверьте раздел «Безопасность» в админ-панели.
- **Нет разделения по объектам.** Редактор может править любой объект. Если команды разные, понадобятся права на уровне объекта.
- **Лимиты хранятся в памяти процесса.** После перезапуска они сбрасываются, а при нескольких процессах считаются отдельно. Для продакшена нужен Redis или лимиты на прокси (nginx).
- **HTTPS.** Flask отдаёт HTTP. Сервер нужно поставить за прокси с TLS и HSTS, иначе токен уходит открытым текстом.
- **SMTP.** Пароль от почты хранится в переменной окружения, используйте отдельный ящик с паролем приложения.
- **Приглашение без почты.** Если SMTP не настроен, администратор видит ссылку и передаёт её сам. Передавайте её по защищённому каналу.
- **SQLite.** Подходит для одного сервера. При росте нагрузки нужна PostgreSQL.
- **Сторонние встраивания** (Google Maps, YouTube) работают в iframe по белому списку CSP. Содержимое этих страниц мы не контролируем.

## Что проверено тестами

`backend/tests/test_api.py` (запуск: `cd backend && python -m unittest discover -s tests`):

- регистрация не даёт роль администратора, в том числе через `PATCH /api/auth/me`; ловушка, слабый пароль, повтор почты и лимит регистраций;

- охота: без входа — 401, засчитываются только настоящие пиксели, в таблице лидеров нет почты;
- проверка загрузок 360° по пропорции и размеру;
- прежние тесты ролей, блокировки, замка редактирования и конфликтов версий.
