# Работа команды

## Кто за что отвечает в коде

| Роль | Основные файлы | Что дальше |
| --- | --- | --- |
| 1. Тимлид, продакт, питч | `README.md`, `docs/`, тексты меток в `frontend/data/template_map.json` | заполнить реальные описания входов, касс, фудкортов; сценарий демо |
| 2. 3D-моделлер | `frontend/src/core/scene3d.js` (`buildStadium`), `stadium.js` | уточнить размеры чаши по чертежам, по желанию — заменить процедурную модель на GLB из Blender |
| 3. 3D/WebGL-разработчик | `scene3d.js`, жесты, режим «взгляд из точки» | плавность на слабых телефонах, этажи, подсветка маршрута |
| 4. Панорамы 360° | `visitor.js` (панорамы), `api/uploads.py` | снять реальные панорамы, склейка кадров с телефона на сервере |
| 5. Фронтенд и UI/UX | `styles.css`, `visitor/`, `admin/` | тесты на телефонах, доступность, PWA |
| 6. Бэкенд и DevOps | `backend/`, `Dockerfile`, `.github/workflows/` | PostgreSQL, деплой на сервер с HTTPS, резервные копии |

## Как работать с репозиторием

1. Каждая задача — отдельная ветка: `git checkout -b feature/panorama-upload`.
2. Небольшие коммиты с понятным описанием: `Добавить загрузку панорам с телефона`.
3. Pull Request в `main`. Перед слиянием CI должен быть зелёным, нужен один просмотр от коллеги.
4. Шаблон карты (`template_map.json`) правьте через админку: экспортируйте черновик и замените файл одним коммитом. Так не будет конфликтов.

## Демо-сценарий

1. Открыть карту с телефона по ссылке.
2. Найти «A105» → «Вид с места».
3. Еда → «Фудкорт · Западная трибуна» → «Маршрут» от КПП «Юг» → «Пройти в панорамах».
4. Войти администратором и нарисовать помещение, поставить метку, опубликовать.
5. Вернуться к карте по той же ссылке: изменения уже видны.
